In about 15 minutes, you can have your own page at

your-username.github.io/my-first-site

No server, no payment, and no command line. You need a web browser and two small text files. This guide takes you from no account to a live link you can send to anyone.

Start with step 1

The GitHub screens below are simplified drawings with the part you need outlined in yellow. The real pages look a little different and GitHub sometimes moves things, but the labels should match.

  1. Create a GitHub account

    Go to github.com/signup and sign up with your email. The free plan is all you need.

    Choose your username with care, because it becomes part of your website address.

  2. Make your two files

    Create a new folder on your computer. Inside it, use any text editor, such as Notepad or VS Code, to save these two files.

    Name the first file exactly index.html, all lowercase. GitHub Pages opens this file first when someone visits your site.

    In Notepad, set "Save as type" to "All files" so the name doesn't end in .txt.

    Double-click index.html to preview it in your browser before you upload it.

  3. Create a repository

    A repository, or repo, is the online folder that holds your site's files.

    Sign in, select the + at the top right of GitHub, and choose New repository.

    Name it my-first-site and set it to Public. Then select Create repository.

    The repo name becomes the last part of your address.

  4. Upload your files

    On your new repo's page, select uploading an existing file.

    Drag in index.html and style.css. Drag the files themselves, not the folder they're in, so that index.html sits at the top level of the repo.

    Scroll down and select Commit changes. A commit is GitHub's word for a saved set of changes.

  5. Turn on GitHub Pages

    Your files are on GitHub now, but they aren't a website yet.

    1. Open your repo's Settings tab.
    2. Select Pages in the left sidebar.
    3. Under Source, choose Deploy from a branch.
    4. Under Branch, choose main and / (root).
    5. Select Save.

  6. Wait for the build

    GitHub now publishes your site, which usually takes a minute or two.

    To watch the progress, open the Actions tab. A workflow called pages build and deployment shows a yellow dot while it runs and a green check when it's done.

  7. Visit your new URL

    Go back to Settings and then Pages. You'll see your address at the top, with a Visit site button.

    The address follows this pattern, with your own username and repo name:

    https://your-username.github.io/my-first-site/

    The link works for anyone, so go ahead and share it.

Change your site later

Open a file in your repo, select the pencil icon, make your edit, and select Commit changes. To replace a file, upload a new one with the same name. Your live site updates within a couple of minutes.

If something goes wrong

I see a 404 page

Wait a few minutes and refresh, since a first build can take a while. If the 404 stays, check that the file is named exactly index.html and sits at the top level of the repo, not inside a folder.

My page shows up, but with no styling

Check that the href in your <link> tag matches the CSS file name exactly. GitHub Pages treats capitals as different letters, so Style.css and style.css are two separate files.

I can't find the Pages options

Check that the repo is public, since Pages on private repos needs a paid plan. You can change this at the bottom of the Settings tab. Also check that you've uploaded at least one file, so that the main branch exists.

My changes don't appear

Check the Actions tab to see whether the build has finished. If it has, your browser may be showing an old copy, so do a hard refresh with Ctrl + Shift + R, or Cmd + Shift + R on a Mac.

This guide is itself just one HTML file and one CSS file, published the same way. Want more detail? Read the official GitHub Pages docs.
